SFDC Build Tool

Describe a Salesforce need in plain language. Review it. Deploy it, or take the package with you.
Try it: salesforce-debugtool.herokuapp.com/flow-tool
Build: create Flows, Apex, LWCs, objects, fields, prompt templates and agents from one request. The model never writes raw metadata XML: it drafts a validated design, and the diagram you approve and the XML that deploys come from that same source, so they cannot disagree.
Where the AI is: the LLM understands the request, splits it into pieces, drafts each design, explains it, and applies your changes. Everything that must be exactly right (validation, XML, approval, deploy) is deterministic code, or you.

Without vs. with an org connection

Not connected (design only)

  • Generate and refine Flows, Apex, LWC, objects, fields, AI prompts, agents, in one plan
  • Diagram, plain-English explanation, generated code, test guide
  • Download the report and a ready Metadata API package (.zip); deploy it yourself with sf CLI / Workbench
  • Share a review link with a colleague
Never contacts a Salesforce org.

Connected to an org

  • Everything on the left, plus:
  • Browse and open existing Flows, Apex, triggers, LWCs, objects, fields, prompts; ask what they do, change them
  • Validate against the real org (check-only, nothing created)
  • Deploy in one transaction, with a link into Flow Builder
  • Org errors go back to the model for a fix, then return for approval
Two ways in: OAuth login, or manual entry (paste your instance URL and session ID), which needs no Connected App and no admin setup.

What it builds today

  • Flow types: record-triggered (before or after save, before delete), scheduled, platform-event-triggered, autolaunched, screen, and orchestration.
  • Flow elements: decisions, loops, get/create/update/delete records, subflows, actions, scheduled paths, pause, custom errors, screens.
  • Other metadata: Apex classes and triggers, LWC, custom objects and fields, platform events, custom metadata, permission sets, prompt templates, Agentforce agents.
  • Preview: Flows render as a diagram; LWCs get a live structural preview of the UI.
  • Customer portal tab: public site, sign-up, My Account, chat.

The report: what you hand to a reviewer

One self-contained HTML file per request (print it to PDF). For every piece it contains the design (diagram, field table or source), the model's reason for the choice, the LWC preview, and how to test it: for a record-triggered flow, a ready SOQL query for a record that satisfies the entry criteria; for a screen flow, the inputs Debug will ask for.

Quick start

From zero to a validated deploy in about 10 minutes. Written for a Salesforce admin; no coding needed.
1
Open it. There is nothing to set up. Go to salesforce-debugtool.herokuapp.com/flow-tool. A model allowance for reasonable use is built in, so you can start immediately. Optional: under Options, paste your own Anthropic API key (BYOK) for heavier use or your own billing and data terms; it stays in your browser only. Leave Model on "provider default" and Effort on medium.
2
Connect an org (optional, use a sandbox first). Without it you can design and download everything; with it you can open existing metadata, validate and deploy. Use Log in (Sandbox) if shown, otherwise Manual entry: paste the instance URL and a session ID. Fastest ways to get the session ID: a Visualforce page containing {!GETSESSIONID()}, or sf org display / sf org auth show-access-token. It is held in the tab only.
3
Pick a mode. Build multiple things one request becomes an ordered plan: objects, fields, Apex, triggers, flows, LWC, platform events, prompt templates, Agentforce agents, deployed together in one transaction (a flow can use a field created in the same request). A single Flow or LWC is simply a one-step plan. Open one from the org an existing Flow, Apex class, trigger, LWC, prompt template, custom object or custom field: have it explained, then change it. An object opens as a plan, with a step per field. Customer portal builds an Experience Cloud site: public home page, self-registration, a My Account page and optional chat.
4
Write the request like a spec. Name the object and fields, the trigger ("when a Request is set to Approved"), the conditions, and the outcome. One process per request. The Examples button has ready specs, from a single field to full solutions and AI examples (a prompt template, a service agent, an employee agent), each saying what you get and what to prepare. Use exact API names for anything that already exists (e.g. Account.Tier__c): the tool does not read your org's schema while designing, so a loosely named field may be guessed wrongly and only fails at Validate.
"Create a Project Request object with a Status picklist (New, Approved, Rejected). Add a flow that, when a request becomes Approved, creates a follow-up Task for the record owner."
5
Review, then refine. Each step is a card. Flows show Diagram, Explain, Documentation, Test and Flow XML; objects show a field table; Apex shows the source; prompt templates show their text and answer keys; agents show their topics and actions; LWC adds a Preview. Not right? Type the change in Change something (or Revise plan to add or remove steps). Warnings sit above the diagram.
6
Approve, Validate, Deploy. Approve unlocks Validate (check-only against the org, nothing created), which unlocks Deploy. Flows deploy as Draft unless you tick Deploy Active. New objects and fields get access on a Permission Set. Agents deploy as drafts: an employee agent can be published and activated from its own step, a service agent (which asks for the Einstein Agent User it runs as) in Agentforce Builder. Any edit after approving requires approving again. The org's own error, if any, is fed back to the model and the fix returns for approval.
7
Take it with you. Download report (HTML: design, reasons, test guide), Download package (.zip) to deploy with sf CLI or Workbench, Push to Git (PR) to commit it to a new branch, or Share this for a 24-hour link plus password so a colleague can pick up the review.

Good to know

If you seeIt means
Validate says a field or object is missingThe request named it loosely and the model guessed. Put the exact API name in the request and revise.
Flow refused when openingIt uses a construct the tool cannot represent exactly (it names it). Refused rather than redrawn wrongly, so nothing is lost on redeploy.
INVALID_SESSION_IDThe session ID expired or belongs to another org. Reconnect.
Apex fails only at ValidatePre-checks are structural (braces, class name); the compile happens in the org, and the error comes back for a repair.
High demand / quota errorThe model provider throttled. Retry, or pick another model in Options.
New flows are created with a GC_ name prefix so they are easy to find. Start in a sandbox, review the Test tab's guide, then promote the package through your normal release path.
